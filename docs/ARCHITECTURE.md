# Architecture and extension points

`main.go` dispatches commands with separate global and command options. `shell.go` tokenizes input without expansion/evaluation; backslashes remain literal and single/double quotes work, with doubled quotes inside a quoted argument. `console_windows.go` reads Win32 KEY_EVENT input for editing, Tab, and session history. The non-Windows build is a development/test harness with line input; Windows collectors explicitly report unsupported OS rather than simulated data.

`model.go` defines configuration and the five statuses. `checks.go` owns policy interpretation, independent of providers. `runner.go` embeds `collectors/*.ps1`, supplies UTF-16 encoded source and JSON input, imposes deadlines, captures bounded output, and validates the envelope. Child processes run without profiles or input prompts. `process_windows.go` attempts descendant termination on cancellation. The application has no installation step, privileges service, daemon, auto updater, scheduler or repair path.

`network.go` handles HTTP/TLS/DNS/TCP natively and invokes bounded Windows ping/tracert. TLS inspection deliberately captures an untrusted peer chain, then independently verifies system trust, hostname and dates before classifying it; HTTP uses normal verification and never skips trust checks. No online revocation checking is implemented. `files.go`, `archive.go`, and `follow.go` implement explicit operations. `report.go` exports escaped HTML, text and structured JSON and performs opt-in retention pruning. Vendor processes are limited to fixed inspection/capture argument forms in `integrations.go`; users cannot send arbitrary PERCCLI mutations.

To add a collector:

1. Add a named script returning `$data` (array) and `$limitations` (array of strings). The runner initializes the limitations array. Use `INCOMPLETE:` at the start of a limitation when collection is actually incomplete; informational scope limitations do not by themselves make successful inventory unknown. Throw on a wholly unavailable provider/tool/permission.
2. Add its command to `collectorNames` and `commandList`, define strictly validated options in `collectorOptions`, and document supported syntax and prerequisites.
3. Add policy interpretation if the new data establishes a health condition; otherwise retain an explicitly scoped inventory result. Never infer health merely from empty data or a missing integration.
4. Add meaningful fixture tests for malformed/unavailable data and policy boundaries. Validate the PowerShell script on the actual Windows target.
5. Add to `healthChecks` only when appropriate to all target installations. Report/watch select read-only collectors; commands requiring arguments are excluded.

PowerShell references: [local CIM associations](https://learn.microsoft.com/en-us/powershell/module/cimcmdlets/get-cimassociatedinstance), [Get-WinEvent filters](https://learn.microsoft.com/en-us/powershell/scripting/samples/creating-get-winevent-queries-with-filterhashtable). Administrators is identified through well-known SID S-1-5-32-544 and Win32_GroupUser, avoiding the localized group name and the 32-bit LocalAccounts module limitation described in [Get-LocalGroupMember](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.localaccounts/get-localgroupmember).

Known limitations: inventories are sequential and can be large; PowerShell JSON nesting is limited to depth 12 and output to 8 MiB. Inaccessible fields are not always separately available from CIM; provider failures return UNKNOWN with stderr. Administrator membership depends on the provider resolving accounts; orphaned domain principals may produce incomplete results. Recursive AD expansion returns leaf members for domain groups, not a complete privilege graph. It does not enumerate delegated privileges, scheduled-task/service impersonation, domain-controller privileges or every route to administrative access. A baseline compares only direct SIDs and flags extras, not missing baseline members.
